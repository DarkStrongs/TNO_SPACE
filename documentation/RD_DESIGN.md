# 研究与发展（R&D）页 设计稿 v1（2026-10-21）

状态：设计稿，未实现。Mockup：files/out/rd_mock_v1.png（生成器 work/rd_mock/gen_mock.py）。
参考方向：TNO: Next Frontier 的「NASA 管理系统」思路——承包商、国会政治、技术成熟度。具体数值和项目均为本 mod 自拟。

## 1. 界面结构（沿用 r4/r5 的页面架构）
- 新增独立容器 `NSP_rd_body`：`parent_window_name = NSP_home_window`，用 flag `NSP_rd_open` 切页，切页方式与 planner 相同。
  - 主页的 visible 条件改为：`NOT planner_open AND NOT rd_open`。
  - `NSP_rd_button` 负责设 flag；返回按钮挂 `shortcut = ESCAPE`。
  - 开窗时同时清除 `planner_open` 和 `rd_open`。
- 页面分区（1075×690）：
  - 顶栏资源条（10,62 / 1055×36）：研发预算、研发槽、科研点、对苏技术差距。
  - 左栏「研发方向」（10,104 / 220×576）：6 个方向页签及各自等级；已完成数；成熟度列表。
  - 中上「技术树」（236,104 / 540×346）：4 个时代列 × 3 行，共 12 个格位。
  - 中下「研发队列」（236,456 / 540×224）：每个研发槽一行，显示名称、承包商、进度条、剩余天数，以及「节约 / 标准 / 加急」三档。
  - 右栏「项目详情」（782,104 / 283×576）：描述、成本、工期、前置、解锁、奖励，承包商竞标三选一，「开始研发」按钮。

## 2. 技术树的引擎实现
- 每个方向都用同一个格位模板（12 格）。节点是静态的 `NSP_rd_node_0..11`，用数组 `NSP_rd_grid^(track*12+slot)` 映射到项目 id；没有项目的格位用元素级 `_visible` 隐藏（元素级可用，容器级不行）。
- 节点 frame 表示 4 种状态：需前置 / 可研发 / 研发中 / 已完成。
- 连线：每个方向一张预绘的连线图（`noOfFrames = 方向数`），放在节点下层；状态只靠节点 frame 表达，连线不逐条变色（逐条变色需要几十个元素，不划算）。
- 项目数据数组（下标 = 项目 id）：
  - `NSP_rd_track` / `_slot`：所属方向、格位
  - `_cost` / `_days`：成本、工期
  - `_req1` / `_req2`：前置项目（-1 表示无）
  - `_year`：最早可研发年份
  - `_state` / `_prog`：状态、进度
  - `_unlock_kind` / `_unlock_id`：解锁内容
  - `_tech`：太空科技奖励
- 队列：数组 `NSP_rd_queue`，长度上限为 `NSP_rd_slots`。
- 周结算（on_weekly，`tag = USA`）：
  - 对队列里每个项目：`prog += 700 / days × 资金倍率 × 承包商速度`，同时扣每周费用，并掷突破 / 挫折事件。
  - 进度满 100 时完成：标记完成 → 解锁内容 → 加 `NSP_tech` → 弹通知事件 → `NSP_recalc_*` → `NSP_dirty += 1`。

## 3. 玩法
1. **研发槽 + 预算**：研发预算来自 NASA 年度拨款中的研发部分，项目按周扣费。三档资金：
   - 节约：花费 ×0.7，速度 ×0.6，挫折率上升
   - 标准：×1
   - 加急：花费 ×1.6，速度 ×1.4
2. **承包商竞标**：每个项目有 2–3 家竞标，成本、工期、风险各不相同。
   - 选谁会影响对应州议员的好感，进而影响国会支持，最后反映到预算上。
   - 长期选同一家：有合作折扣，但会触发「垄断听证」事件。
3. **解锁直接接到现有系统**：
   - 规划器的修正：新增 `NSP_mod_unlocked^m`，调色板只显示已解锁的修正
   - 载荷、运载火箭、发射场、目的地（地月转移需要 F-1 + J-2 + 土星 V）
   - 计划切换门槛（水星 → 双子星 → 阿波罗）
4. **技术成熟度**：新技术首飞时可靠性 -15%；每次成功飞行 +5%，直到成熟（回到 0）。
   - 飞行失败会触发「事故调查」事件：停飞若干天，可以换取成熟度或改型。
   - 这部分接在规划器的可靠性计算 `NSP_calc_rel_vehicle` 上。
5. **突破 / 挫折事件**：每个研发中的项目每周约 2% 概率触发，如 F-1 燃烧不稳定。选项一般是：加钱 / 延期 / 冒险继续。
6. **竞赛压力**：顶栏显示对苏 / 对德的技术代差。
   - 落后时：国会追加拨款，但民意焦虑。
   - 领先时：会出现削减预算的压力（对应历史上阿波罗之后的削减）。
7. **时代门槛**：项目有最早年份，避免 1960 年就能研发土星 V。

## 4. 六个方向的节点草案
- 运载火箭：红石改进型 / 宇宙神载人化 / 改进型发动机 → 大力神 II GLV / 半人马上面级 / 捆绑助推器 → F-1 / J-2 → 土星 IB、土星 V
- 载人航天器：水星舱改进 → 双子星飞船 → 先进双子星改装 → 阿波罗 CSM → 登月舱 LM
- 生命保障 / 舱外：加压服 → 基础舱外活动系统 → 长期驻留（14 天）→ 月面服
- 导航与对接：雷达交会 → 基础对接系统 → 阿波罗制导计算机 → 月球轨道交会
- 无人探测：TIROS → 徘徊者 → 勘测者 → 水手号 → 月球轨道器（为登月选址，计入目标）
- 地面设施：任务控制中心 → 39 号发射台 → 垂直总装大楼（研发槽 +1）→ 深空网络

## 5. 分期
- r10：页面框架、切页、静态布局、本地化（不带逻辑）
- r11：数据数组、技术树显示、开始研发、队列、周结算、完成与解锁
- r12：承包商竞标与国会好感、资金档、突破 / 挫折事件
- r13：成熟度接入规划器的可靠性；竞赛压力

## 方案 A：三栏管理台（v1）
左栏方向、中间技术树 + 队列、右栏详情。信息最全，但技术树只占三分之一宽度。

## 方案 B：TNO 原生蓝图科技树（推荐作为主界面）
- 布局照搬 TNO 科技树：分类页签 + 年代轴 + 行标签 + 蓝图卡片 + 橙色当前时代框。选中卡片后，底部抽屉显示详情、承包商和开始按钮。
- 实现要点：
  - 卡片用静态按钮，frame 区分 4 种状态，线稿画在 DDS 上，每个项目一帧（或每类一张图集）。
  - 每个分类一张预绘的连线图。
  - 底部抽屉是固定容器，内容由 `NSP_rd_sel` 决定。
  - 行和列固定（4 行 × 5 个年代），比 A 更贴近玩家熟悉的 TNO 界面。

## 方案 C：合同看板
- 五列：提案 → 竞标 → 研发 → 测试 → 服役。项目卡在各列之间移动。
- 底部显示承包商关系条（好感度对应州议员支持；高好感有长期合作折扣，低好感会抬高报价）。
- 引擎上，每列是一个 gridbox，数据来自五个数组（`NSP_rd_col0..4`）；状态改变时在数组之间移动 id。
- 适合做成 B 的第二个页签「合同」，而不是替代 B。

## 方案 D：竞赛时间轴
- 横轴是 1958–1972 年。三条泳道：NASA / RLR（德）/ JBAPD（日），对应 TNO: Next Frontier 的三家机构。
- 实心菱形 = 已完成，空心 = 计划，圆圈 = 情报（不确定）。
- 下方是研发甘特条，用连线指向它们支撑的里程碑。
- 底部面板显示下一个里程碑、对手可能抢先的情报，以及三种操作：加急 / 冒险（跳过测试）/ 情报核实。
- 适合放在主页，或做成 R&D 的第三个页签「竞赛」。

## 玩法模块菜单（可任选组合）
1. 承包商竞标 + 州议员好感（C 的底条）
2. 测试阶段：研发完成后要过地面 → 无人 → 载人测试，每个阶段可以跳过，跳过换取可靠性惩罚（即技术成熟度的另一种做法）
3. 突破 / 挫折事件（燃烧不稳定、焊缝裂纹、软件溢出…）
4. NASA 研究中心：马歇尔（火箭）/ 载人航天中心 / 喷气推进实验室（无人）/ 兰利（理论）。项目指派到中心，各中心有专长加成和负载上限。研发槽 = 中心数量
5. 人才争夺（TNO 背景：火箭专家多在德国）：德国科学家叛逃事件、招募计划、雇佣外籍专家的政治代价
6. 军方技术溢出：与 TNO 原版导弹 / 喷气技术挂钩，空军和陆军的 ICBM 技术可以降低运载火箭的研发成本，代价是军方插手任务优先级
7. 情报与反情报：花钱核实对手进度、窃取图纸（研发 +x%）、防止泄密
8. 争议路线选择（不可兼得）：直接上升 / 地球轨道交会 / 月球轨道交会 三选一，决定后续的技术树分支
9. 年度预算听证：每年 1 月审议，依据成果 / 竞赛态势 / 承包商游说决定下一年预算，可以选择游说策略
10. 风险容忍度：一项全局指标，事故后下降，会锁住「冒险」类选项
